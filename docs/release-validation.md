# 0.3.2-rc.1 verification

This candidate advances the 0.3.1 development tree and the last published
v0.2.44 release. Its version is shared by Cargo, the pinned runtime definition,
CLI output, artifact manifest, and package name.

Verified during this closure:

- Windows: 14 integration tests pass; Linux: 15 integration tests pass.
- Windows and Linux release binaries build from the same source.
- Linux laboratory `poc031`: doctor reports HOST_READY; apply reports READY with
  Access, Control and Compute healthy after explicit Tailscale authorization.
- Compute health authenticates to Proxmox and checks active storage.
- CoreDNS probes assert authoritative answers, NXDOMAIN and REFUSED over UDP/TCP.
- Control serves the Proxmox UI over hostname-verified TLS, using its public CA;
  both compute.gnx and proxmox.gnx returned HTTP 200 from the private namespace.
- All four laboratory services are generated by Quadlet.
- Unchanged apply returns READY with the same revision. Restarting laboratory
  Access also returns to READY with all capabilities healthy and the same revision.
- The elevated Windows installer was executed and safely refused pre-existing
  C:\ProgramData\GNX state with EXISTING_STATE. It did not overwrite that state.
- The rootfs is built from an official Ubuntu image with verified SHA-256 and
  signed Ubuntu package repositories. It is not an export of a user's WSL instance.

Corrections include the missing test intent, a false-negative Proxmox health
probe (the API version endpoint returns 401 anonymously), persisted release
revision, reserved DNS names, LF shell scripts, and a compiled Windows installer.

Not yet accepted: external-client HTTPS (Windows connection timed out), normal
client split DNS, clean Windows dedicated-account bootstrap, native Linux on a
separate host, full reboot, failure-injection recovery, authenticated in-place
upgrade/rollback, and complete G0-G6 parity. No final release acceptance is claimed.
The existing mesh.gnx/proxmox.mesh.gnx installation is preserved.

Build: `packaging/windows/build.ps1 -Rootfs dist/gnx-wsl-rootfs.tar.gz`.
The release manifest contains SHA-256 hashes for every executable and Linux bundle
plus the prepared WSL rootfs. Verify the manifest digest from the release before
running the installer. The hashes provide integrity through that trusted channel;
these executables do not claim Authenticode signing.
